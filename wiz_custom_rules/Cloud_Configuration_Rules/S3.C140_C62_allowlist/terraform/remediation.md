Give each bucket an `aws_s3_bucket_server_side_encryption_configuration` with `sse_algorithm` set to `aws:kms` (or `aws:kms:dsse`) and, in `kms_master_key_id`, the ARN of a key authorized for the bucket: one from `authorized_kms_key_ids`, or from the bucket's own entry in `authorized_kms_key_ids_by_bucket`. A bucket without the configuration gets SSE-S3, and `aws:kms` without a key uses the AWS managed key `aws/s3`. Name the key by its ARN, never by an alias. A bucket in `sse_s3_buckets` may keep SSE-S3. The inline `server_side_encryption_configuration` block of `aws_s3_bucket` is deprecated; do not set both for one bucket.

```hcl
resource "aws_s3_bucket_server_side_encryption_configuration" "example" {
  bucket = aws_s3_bucket.example.id

  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm     = "aws:kms"
      kms_master_key_id = "arn:aws:kms:<region>:<account-id>:key/<key-id>"
    }
    bucket_key_enabled = true
  }
}
```

An object that `aws_s3_object`, `aws_s3_object_copy` or `aws_s3_bucket_object` uploads either leaves `server_side_encryption` and `kms_key_id` unset, to take the bucket default, or sets `kms_key_id` to a key ARN authorized for its bucket. An `aws_s3_object_copy` that sets `customer_algorithm`, `customer_key` or `customer_key_md5` encrypts the copy with SSE-C and is reported; drop them and name an authorized `kms_key_id`. Replace `<region>`, `<account-id>` and `<key-id>` with those of an authorized key.

Default encryption generated by a `dynamic` block cannot be read and is reported; write the block out.
