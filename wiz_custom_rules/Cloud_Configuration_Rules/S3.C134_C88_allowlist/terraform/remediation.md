Match each enabled rule to its route in `authorized_replications`, writing the destination and key ARNs exactly as the route lists them.

```hcl
resource "aws_s3_bucket_replication_configuration" "example" {
  bucket = aws_s3_bucket.example.id

  rule {
    id     = "to-replica"
    status = "Enabled"

    source_selection_criteria {
      sse_kms_encrypted_objects {
        status = "Enabled"
      }
    }

    destination {
      bucket = "arn:aws:s3:::example-replica-bucket"

      encryption_configuration {
        replica_kms_key_id = "arn:aws:kms:<region>:<account-id>:key/<key-id>"
      }

      replication_time {
        status = "Enabled"
        time {
          minutes = 15
        }
      }

      metrics {
        status = "Enabled"
        event_threshold {
          minutes = 15
        }
      }
    }
  }
}
```

A route with a replica key needs `source_selection_criteria` and `encryption_configuration`; one that requires Replication Time Control needs `replication_time` and `metrics`. Add `access_control_translation` with `owner = "Destination"` only where the route passes ownership. A bucket not in `authorized_replications` is left to S3.C87, and a value known only at apply is not judged here.

The inline `replication_configuration` block of an `aws_s3_bucket` is checked the same way under its own names: `rules` blocks, `replica_kms_key_id` and `account_id` set on the `destination`, and `sse_kms_encrypted_objects` with `enabled = true`. There a `metrics` or `replication_time` block with no `status` is enabled. The provider deprecates the inline block in favor of `aws_s3_bucket_replication_configuration`.

A rule, or a block its route needs, generated by a `dynamic` block cannot be checked against the route; write it out.
