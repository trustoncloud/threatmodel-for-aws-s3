Set `role` to an ARN listed under the source bucket's name in `authorized_replication_roles`, or add the role under that bucket once approved.

```hcl
resource "aws_s3_bucket_replication_configuration" "example" {
  role = "arn:aws:iam::<account-id>:role/<role-name>"
}
```

A role listed only for another bucket fails, and so does a bucket with no entry. The source bucket is read from `bucket`, as a literal name or a reference to an `aws_s3_bucket` with a literal `bucket`; the inline `replication_configuration` block of an `aws_s3_bucket` is checked the same way, with its `role`. The ARN must match a listed one exactly, account and partition included. A role given as a reference to another resource is known only at apply and is not compared here. When only the source bucket is known at apply, a role listed for no bucket still fails, and any other role is left to the cloud check.

An inline `replication_configuration` generated by a `dynamic` block does not show its role; write the block out, or move to `aws_s3_bucket_replication_configuration`.
